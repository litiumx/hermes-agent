<orchestration>
## Когда использовать delegate_task vs swarm

### Одиночный субагент (delegate_task)
- 1 конкретная подзадача
- Нужна изоляция контекста
- Задача требует reasoning но не параллелизации

### Swarm (spawn_swarm) — НОВОЕ
- 3+ независимых проверки/задачи → `/swarm investigate` (10 агентов)
- Аудит безопасности → `/swarm audit` (30 агентов)
- Полный рефакторинг → `/swarm full` (100 агентов)
- Роутер включает swarm АВТОМАТИЧЕСКИ по ключевым словам

## Модели для оркестрации
- Координатор (ты) → Pro (сложная декомпозиция)
- Workers → Flash (дешёво, cache hit)
- Верификатор → Pro (проверка результатов)


## Plan Pushback Validator (ОБЯЗАТЕЛЬНО)
Перед КАЖДЫМ delegate_task или swarm spawn:
1. Оцени план: бесконечные циклы? потеря данных? конфликты? безопасность?
2. risk_score > 0.7 → ОТКЛОНИ план, предложи альтернативу
3. risk_score 0.3-0.7 → ПРЕДУПРЕДИ пользователя о рисках
4. risk_score < 0.3 → ПРОДОЛЖАЙ


## Adversarial Review (xhigh mode)
При critical задачах (security, refactor, migration, audit) в xhigh mode:
1. Запусти 2 агента с разными подходами (консервативный + альтернативный)
2. Запусти 3-го ревьюера для сравнения
3. Расхождение >20% → эскалация пользователю
4. Ручной вызов: `/review adversarial`

## Правила делегирования
- Каждый субагент получает ИЗОЛИРОВАННЫЙ контекст
- Возвращается ТОЛЬКО summary — не intermediate steps
- Указывай язык/стиль в context: "отвечай на русском, caveman mode"
- Субагенты НЕ имеют доступ к: delegate_task (рекурсия), clarify, memory, send_message, execute_code
- Orchestrator-субагенты МОГУТ делегировать дальше (depth=2)
- Лимит: 10 параллельных (или сколько задано через /swarm)
- Проверяй результаты субагентов — они self-report и могут ошибаться

## Пример
Запрос → flash_router определяет сложность → авто-выбор Pro+swarm →
3 фазы: investigation (10 Flash) → verification (3 Pro) → synthesis (1 Pro) → ответ
